# Поиск видео в управляемом браузере

9 ноября 2026 · этап 4 функционального плана принят по автоматическим проверкам и независимому read-only ревью. Реализован ограниченный первый результат: поиск YouTube, список названий/каналов, явный выбор и открытие страницы выбранного видео. ИИ, API-ключи и платные сервисы не нужны. JARVIS не отправляет команду воспроизведения; состояние плеера не проверяется.

## Как пользоваться

В «Сайты → Видео YouTube» нажать «Открыть управляемый браузер». JARVIS запускает отдельное окно установленного Microsoft Edge или Google Chrome. Затем ввести запрос в этой вкладке либо сказать/ввести «найди видео [запрос]». Появляются до пяти результатов с названием и каналом. Выбрать строку и нажать «Открыть выбранное» либо ответить «вариант один», «вариант два» и т. д. Даже единственный результат требует явного выбора.

После открытия JARVIS сверяет URL выбранной вкладки, canonical video ID и наблюдаемое название документа. Ответ содержит окончательный стандартный URL `https://www.youtube.com/watch?v=…` и название. Формулировка «Страница видео открыта. Воспроизведение не проверено» намеренно не обещает звук или работу плеера. Для остановки доступна кнопка на странице; голосовая задача при уже включённом пользователем микрофоне принимает «останови задачу» / «отмени задачу». Текстовый поиск и кнопки микрофон не включают.

## Границы и интеграция

- `BrowserVideoService` в Core выполняет фиксированный алгоритм с `IVideoBrowserSession`; production фабрика в `MainViewModel` создаёт `ManagedVideoBrowser`, использующий .NET `ClientWebSocket` и CDP. Это поставляемый код JARVIS, не инструменты браузера Codex и не тестовая заглушка.
- Запуск браузера только по явной кнопке. При запуске JARVIS браузер и поиск не стартуют. При отсутствии поддерживаемого установленного браузера показывается ограничение; установки/загрузки нет.
- Новый случайный профиль под `work/browser-sessions/<guid>`, собственный процесс и собственная начальная `about:blank` вкладка. Существующие личные браузеры, вкладки, cookies и токены не перечисляются и не читаются. При выходе из JARVIS закрывается только собственный процесс; удаляется только созданный профиль после проверки абсолютного пути. Это временный браузер, не место для хранения входов и работы.
- CDP слушает случайный порт, взятый из `DevToolsActivePort` нового профиля. Перед подключением проверяются PID владельца и loopback адреса IPv4/IPv6. Подключение привязано к конкретному browser endpoint, target ID и flattened session ID. Подмена конфигурацией чужого порта или личного профиля не поддерживается.
- Только построенные приложением HTTPS-адреса поиска/просмотра `www.youtube.com`; video ID строго 11 допустимых символов. Верхние Document-переходы перехватываются Fetch и должны точно совпасть с ожидаемым URL. Другие адреса и перенаправления блокируются. Поддокументы не управляются и их Document-навигации блокируются. Загрузки запрещены.
- Данные страницы недоверенные: ограниченный постоянный DOM-reader, до 20 кандидатов/5 допустимых результатов, ограничение длины текста. Никакой код/селектор/URL модели не исполняется. Нет кликов, согласий, входов, подписок, покупок, отправок, загрузок или снимков экрана.
- Новая вкладка, потеря/закрытие/crash закреплённой вкладки, диалог и запрещённый переход останавливают текущую навигацию. Повторная явная кнопка подключения заменяет сломанную сессию. Если сайт требует согласие/вход, автоматический путь честно прекращается; пользователь может открыть видео самостоятельно в обычном браузере. Обход consent/login не реализован.
- Выбор привязан к результатам поиска: перед открытием перепроверяются URL и exact ID/title/channel в актуальном DOM. Новый поиск, Stop, новый разговор/смена AI scope, несвязанная команда и отмена/таймаут голосового выбора очищают выбор. Обычная навигация интерфейса не прекращает прослушивание.
- Действия ограничены 30 секундами, подключение — 20. Для нового документа проверяется loaderId, для поздних метаданных есть короткое ограниченное ожидание. Unsupported DOM, пустой результат, таймаут и несовпадение canonical/title возвращают честную ошибку.
- Session/generation и cancellation проверяются перед принятием результата. Fetch continuation/fulfillment используют отдельный navigation token; Stop/новая вкладка инвалидируют его до отправки в сокет. Очередь stopLoading завершается перед следующей навигацией. Уже совершившийся переход не объявляется отменённым.
- Локальные сценарии/действия ИИ не расширены новым `LocalActionKind`. Browser-команда имеет собственный typed маршрут, фраза зарезервирована от сценариев. Ранее сохранённый сценарий с новой зарезервированной фразой не может неожиданно запустить браузер через кнопку «Запустить»: редактор просит изменить фразу.

## Автоматические проверки

Core fake CDP/session: явные команды, URL/ID ограничения, поиск без auto-select, точный выбранный ID, title/canonical без плеера, устаревший DOM/title/channel/URL, Stop, поздний ответ транспорта, повторное подключение broken-but-alive session, таймаут и неправильные запросы. VM в общем STA lifecycle: кнопочное подключение, текстовый поиск/выбор, отсутствие микрофона/ИИ, старое подтверждение питания, очистка выбора, голосовой interrupt и поздний ответ после Stop, старый сценарий с reserved phrase.

`ManagedVideoBrowserTests` запускает настоящий установленный Chromium (Edge/Chrome) headless в собственном профиле. HTML из `tests/fixtures/browser-video` подставляется через CDP Fetch в выбранный документ; DNS в тестовой сессии заблокирован, прочие запросы отклоняются. Проверяются настоящий DOM и транспорт: несколько результатов, открытие без плеера, поздние canonical/title, изменённый DOM при прежнем URL, unsupported DOM, consent, redirect, новая вкладка, остановка до queued fulfillment и новая вкладка до queued navigation. Браузерный тест выполняется отдельно от временных WPF-тестов, чтобы запуск Chromium не мешал коротким UI timers.

**Это не проверка публичного сайта YouTube и не проверка сетевой доступности, текущей верстки, аккаунтов или воспроизведения.** Реальные микрофон, звук, личные браузеры и desktop screenshots в автоматической приёмке не используются.

Полный .NET Release прогон: **461/461 Core и 52/52 App**, без предупреждений сборки. Собственный WPF-рендер: **64 сочетания**, проверка границ поиска/подключения/списка, фактической ширины строк и текстовых контейнеров title/channel, доступного имени поиска. PNG light-en-collapsed и dark-ru-collapsed просмотрены после исправления наследования стиля боковой панели. Отдельный рендер: `work/browser-video-preview`, RU/EN, light/dark, обычная/минимальная ширина, открытая/свёрнутая боковая панель, 100/125/150/200% raster scale, длинные названия. Масштабирование собственного render не равнозначно переключению системного DPI на устройствах.

## Ручная проверка публичного YouTube

После установки пользователем: открыть управляемый браузер кнопкой → «найди видео [запрос]» → увидеть названия/каналы → выбрать второй результат → сверить показанные название/canonical URL с вкладкой. Проверить Stop во время поиска и «отмени задачу» при голосовом вводе. Если consent/login/блокировка сети или изменённый DOM мешают пути, записать точное ограничение; не считать локальные фикстуры доказательством работы сайта. Кинопоиск, другие сайты, login/consent automation, универсальное управление браузером и этап 5 здесь не реализованы.
