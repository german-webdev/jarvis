## Навыки разработки интерфейсов

Найти на GitHub и в других каталогах навыки именно для интерфейсов настольных приложений Windows: WPF / XAML, Windows/Fluent, работа с клавиатурой, масштабирование, доступность, таблицы и диалоговые окна. Навыки для лендингов и веб-сайтов не считать подходящей заменой.

Оценивать кандидатов по содержанию: визуальная иерархия, типографика, плотность, единые отступы, состояния элементов, контраст, светлая/тёмная палитра, тематическое оформление JARVIS без ухудшения читаемости. Проверять инструкции и лицензии до установки; никакой найденный навык пока не установлен.

### Результат поиска · 9 ноября 2026

Проверены актуальные файлы через GitHub, а не только описания поисковой выдачи. Это оценка инструкций и применимости, не испытание качества сгенерированного интерфейса. Установка навыков, запуск их установщиков и изменение интерфейса в рамках поиска не выполнялись.

**Основной рекомендуемый кандидат — [KrickmanC/ui-ux-pro-max](https://github.com/KrickmanC/ui-ux-pro-max), [SKILL.md](https://github.com/KrickmanC/ui-ux-pro-max/blob/main/SKILL.md).** Самостоятельный текстовый навык без скриптов и внешних баз. Описывает WPF Grid/DockPanel, ResourceDictionary/DynamicResource, общую палитру по смысловым ролям, плотность элементов, DataGrid и виртуализацию, клавиатуру/фокус, DPI 125–200%, длинные переводы, светлую/тёмную/контрастную темы и состояния ошибок/загрузки. Подходит существующему WPF/.NET 10 JARVIS без смены платформы. По прочитанному содержанию это наиболее подходящая база для работы над единым оформлением; результат ещё нужно проверить на конкретном окне. Лицензия репозитория MIT проверена отдельно. Blob SHA прочитанного SKILL.md: `75de393d376f27bc4c3b4f7e360716cd0bc8fce4` (это хеш файла, не коммита).

У кандидата есть собственный этап подтверждения области изменений перед правками и запрет самостоятельно добавлять зависимости; уже явно согласованный объём он разрешает выполнять без повторного вопроса. При применении учитывать действующие инструкции пользователя и проекта. Готовой индивидуальной палитры или макета JARVIS навык не содержит: это нужно разработать отдельно.

**Дополнительные образцы — [Desktop UI Design Skills Pack](https://github.com/umutc6230/ui-design-skills-pack).** Из набора прочитаны:

- [Fluent Windows 11 UI](https://github.com/umutc6230/ui-design-skills-pack/blob/main/skills/07-fluent-windows-11-ui/SKILL.md): иерархия, цвета, типографика, навигация, состояния элементов.
- [Settings-First UI](https://github.com/umutc6230/ui-design-skills-pack/blob/main/skills/13-settings-first-ui/SKILL.md): категории настроек, подписи, проверка полей, несохранённые изменения, действия сохранения.
- [Data Table Admin UI](https://github.com/umutc6230/ui-design-skills-pack/blob/main/skills/14-data-table-admin-ui/SKILL.md): поиск, фильтры, таблицы, выбранные строки и состояния пустого результата.
- [AI Chat + Tool Panel UI](https://github.com/umutc6230/ui-design-skills-pack/blob/main/skills/15-ai-chat-tool-panel-ui/SKILL.md): видимый ход выполнения, остановка и результаты инструментов — полезно для будущего агентного режима.

Лицензия MIT проверена. Ограничения: инструкции преимущественно на турецком; много CSS и шаблонных композиций, местами разные рекомендации по размерам. Для WPF требуется перевод идей в ресурсы/стили и согласование размеров, а не буквальное копирование. README ссылается на другой путь репозитория (`palamut62/desktop-ui-design-skills-pack`), чем найденная и прочитанная ссылка; при установке уточнить канонический источник и зафиксировать версию. Не подключать все 19 визуальных стилей одновременно.

**Прочие рассмотренные варианты:**

- [Syncfusion WPF UI Builder](https://github.com/syncfusion/wpf-ui-builder): действительно WPF, включает работу с темами, компоновкой и проверками. По README требует Syncfusion-компоненты и соответствующую лицензию (commercial/community/trial), предусматривает установку пакетов. Для нынешнего JARVIS не выбран: это дополнительная зависимость и отдельное решение о лицензировании; право на Community License здесь не проверялось.
- [Windows LOB XAML от Microsoft](https://learn.microsoft.com/en-us/windows/apps/get-started/line-of-business/windows-lob-xaml-skill): полезная официальная методика настольных интерфейсов, но реализация ориентирована на WinUI 3. Не подключать как прямые WPF-инструкции.
- [desktop-wpf от j4flmao](https://github.com/j4flmao/agent-skills/blob/main/skills/desktop/wpf/SKILL.md): в основном архитектура и код, меньше конкретного дизайна. В актуальном файле есть спорные/некорректные для стандартного WPF примеры: обычный TextBox с Watermark и сокращённая запись Grid.ColumnDefinitions. Не выбран как основа. Поисковая выдержка также оказалась устаревшей относительно реального файла; оценивать только прочитанный источник. [Microsoft показывает отдельную реализацию placeholder для WPF TextBox](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/controls/how-to-add-a-watermark-to-a-textbox).
- [windows-design из Stark](https://github.com/f0d010c/stark/blob/main/skills/windows-design/SKILL.md): упоминает WPF в описании, но реальные маршруты — WinUI/Tauri/Electron. Содержит жёсткие платформенные предписания, которые не подходят текущему WPF и поддержке Windows 10. Не выбран.
- [WpfUI-Skill от shunnet](https://github.com/shunnet/SKILLS): по README привязан к собственному Snet WPF-стеку. Не выбран для косметического обновления существующего проекта.

**Предлагаемое применение:** основной навык KrickmanC + выборочные композиционные идеи для настроек/каталогов, с проверкой по официальной [документации Fluent в WPF](https://github.com/dotnet/wpf/blob/main/Documentation/docs/using-fluent.md). Сохранить WPF и текущие функции. Сначала определить единые цвета, типографику, отступы, размеры и состояния; затем показать одно реальное окно JARVIS с демонстрационными данными. После оценки распространить систему на остальные окна. Автоматическая установка всех найденных навыков или переход на WinUI не согласованы.

Начальная база для проверки качества: [Microsoft — правила дизайна Windows](https://learn.microsoft.com/en-us/windows/apps/design/), [стили и темы WPF](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/controls/styles-templates-overview). Это документация платформы, не найденные готовые навыки.

После отбора: подготовить согласованный набор цветов/типографики/компонентов для JARVIS и показать образец одного реального окна. Затем последовательно привести основные окна, каталоги и настройки к одному оформлению. Проверять русский/английский текст, маленькие окна и масштаб Windows. Переписывать WPF на другую платформу ради оформления не запланировано.

## Звуковое сопровождение

Кандидат найден: [Kenney Interface Sounds](https://kenney.nl/assets/interface-sounds), на странице указан CC0; [пояснение автора по лицензиям](https://kenney.nl/support). Файлы ещё не скачаны и не встроены. Перед включением сохранить лицензию конкретного набора и указать происхождение в THIRD-PARTY.

Следующая работа: подобрать короткие различимые сигналы готовности, завершения, отмены и ошибки; прослушать варианты и выбрать единый характер звучания. Учитывать пожелание о тематике JARVIS. Не заменять звуками понятный текст ошибки.

Предусмотреть отдельное включение/выключение сопровождения, регулировку громкости и предварительное прослушивание. Проверить, что звук не перекрывает начало команды, не вызывает повторную активацию, не конфликтует с TTS и не превращает каждое нажатие в уведомление. Нынешний сигнал на имя сохраняется до проверки замены. Подбор роботизированного голоса по-прежнему отложен.
