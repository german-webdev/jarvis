> Исторический документ. План и промпт отменены последующим запросом пользователя; описание выпуска не отражает исходники после отката. Актуальное состояние: [ROLLBACK-2026-11-09.md](ROLLBACK-2026-11-09.md). Сабагентов не использовать.

9 ноября 2026. Исходная версия **0.13.5**. **Этапы 1–5, включая отдельную обязательную подзадачу голосового прерывания, реализованы и прошли автоматические проверки и независимое ревью. Общий локальный выпуск **0.14.0** готов; результаты, комплект и ручная проверка — [RELEASE-0.14.0.md](RELEASE-0.14.0.md).** Это текущий порядок функциональной разработки; исторические списки следующих шагов в PROJECT-OVERVIEW.md и SESSION-HANDOFF.md его не меняют.

Работать последовательно: отдельный исполнитель с чистым контекстом на задачу, затем проверка руководителем. Следующий этап начинается после приёмки предыдущего. Не смешивать этапы с широким редизайном или заглушками будущих функций.

## Исходное состояние

Проверено по исходникам до изменений этапа 1, без запросов к аккаунтам и моделям:

- `AiService` передаёт только текущий вопрос. `HttpAiClient` отправляет system + user в OpenAI-совместимый API/Ollama; `ChatGptPlanClient` — один user в Responses, `store=false`, успех только после `response.completed`.
- Claude работает через `SubscriptionClient` без persistence и инструментов. Старый маршрут Codex CLI сохраняется для совместимости; основной ChatGPT использует прямое подключение, возвращать его на CLI не нужно.
- `SkillDispatcher`, `ISkill`, `CommandRequest`, `BuiltInSkills` выполняют локальные действия, но нейросеть их пока не вызывает. Общий системный текст прямо сообщает об отсутствии инструментов.
- Пятисекундное ожидание следующей команды не является памятью ИИ. `LaunchConversation` хранит уточнение выбора приложения. `MainViewModel._session` защищает текущую операцию/речь и меняется между обычными голосовыми репликами — его нельзя использовать как единственный идентификатор диалога.
- В 0.13.5 озвучивание разбивается на части. Сам текст ответа всё ещё проходит `HttpAiClient.CleanAnswer`: 1800 символов плюс многоточие. Контекст не обещает сохранить исходный необрезанный вывод провайдера.
- Реальный ответ ChatGPT уже подтверждён скриншотом пользователя; историческое «ответ модели не проверен» устарело. Это не подтверждение контекста, других провайдеров или будущих инструментов.

## 1. Контекст ИИ и «Новый разговор» — принят

Реализован 9 ноября 2026: 369 Core и 38 Windows тестов прошли, собственный WPF-рендер 32 сочетаний. Контракт, гонки, ограничения реальных провайдеров/голоса и передача следующему исполнителю — [DIALOGUE-CONTEXT.md](DIALOGUE-CONTEXT.md). Автоматическая приёмка не заменяет пользовательскую проверку реального разговора.

**Первый результат:** пользователь задаёт вопрос, затем уточняет «объясни второй пункт проще»; JARVIS передаёт предыдущие реплики. Текст и голос используют один разговор. Компактное действие **«Новый разговор»** на главной очищает контекст и отменяет текущий ответ, доступно во время ожидания и не запускает микрофон. Достаточно компактной кнопки/подсказки, без постоянных поясняющих абзацев и лишнего индикатора контекста. Без списка бесед, постоянной памяти и отдельного нового экрана чата.

**Согласованный контракт:** только память процесса; максимум **8 завершённых пар user/assistant и 16 000 символов сохранённой истории**, одновременно оба ограничения. Новый вопрос сохраняет предел **1–4000 символов**. Для отправки — не более **16 000 символов текста реплик вместе с текущим вопросом**; под него заранее освобождается место удалением старейших пар целиком. Системные инструкции/обрамление учитываются отдельно. Текущий вопрос не обрезать. Это предел по символам, не гарантия вместимости любой модели в токенах. Не делать скрытых повторных платных запросов при отказе провайдера.

Хранить только принятые успешные пары атомарно. Ошибка, пустой/незавершённый ответ, таймаут и отмена не добавляют ни вопрос, ни служебное сообщение. Сохранять полученный UI текст после действующего `CleanAnswer`; ошибка последующего озвучивания не стирает успешную пару. Перезапуск очищает память. Не добавлять личные каталоги, локальные команды, журнал или снимки экрана и не писать новую историю на диск.

После ответа ИИ продолжение может идти в тот же разговор; распознанные локальные команды, уточнения и подтверждения сохраняют приоритет. Явное «Спроси нейросеть …» работает независимо от настройки обращения к ИИ для неизвестных команд. Не превращать любой ввод после ИИ в безусловный запрос к модели.

Историей управляет JARVIS, адаптеры получают один неизменяемый снимок:

| Маршрут | Передача контекста |
|---|---|
| API / Ollama | system, сохранённые user/assistant, текущий user в существующем `messages` |
| Прямой ChatGPT | `instructions` отдельно, user/assistant в `input`; сохранить `store=false`, завершение SSE, без зависимости от удалённого conversation ID |
| Claude | Ограниченный сериализованный контекст с явными ролями и текущим вопросом через stdin; экранирование и отделение данных от system prompt; сохранить запрет persistence, tools, MCP и браузера |

Текстовый контекст Claude не равен нативному многоролевому протоколу: локальные тесты подтверждают сборку запроса, качество следования истории проверяется отдельно. Не включать инструменты CLI ради памяти.

**Очистка и поздние ответы:** отдельные scope активного подключения, generation разговора и отмена текущего запроса; `_session` остаётся дополнительной защитой UI/речи. Инвалидировать старую операцию до очистки, а перед записью пары, показом, журналированием, озвучиванием и продолжением прослушивания проверять актуальность. Одного токена недостаточно — транспорт может ответить после отмены. Проверка и запись истории атомарны относительно сброса; последовательные запросы не конкурируют за одну историю.

- «Новый разговор» отменяет запрос, речь и продолжение прослушивания, очищает историю и текущие карточки. Не обещает удалить уже отправленные данные у провайдера или старый журнал приложения; журнал никогда не является источником контекста.
- Смена активного подключения, модели, провайдера, адреса, ключа/компонента; отключение ИИ; удаление активного подключения; повторный вход/выход активного аккаунта очищают контекст и запрещают старому ответу попасть в новый разговор. A→B→A не восстанавливает старую историю. Учитывать изменение параметров при том же ID.
- Вход/выход сейчас вызываются из `AiConnectionsPage` напрямую через `ChatGpt`/`Subscriptions`: предусмотреть сигнал инвалидации и для них. Обычное обновление access token того же аккаунта не начинает новый разговор. Секреты не входят в диагностический scope/историю.
- Stop отменяет незавершённый запрос и очередь речи, сохраняя завершённые пары. Переход между обычными голосовыми сессиями, переименование подключения и сохранение темы не очищают историю. Инвалидация должна остановить и ответ, принятый сервисом непосредственно перед сменой подключения, но ещё не показанный/озвученный.

**Зависимости:** текущие адаптеры, MainViewModel, локализация. Перед UI-правками прочитать действующие инструкции оформления JARVIS; RU/EN, обычная/минимальная компоновка. Mini использует общий разговор и Stop, отдельный чат не нужен.

**Готовность и проверки:** тесты с подставными HTTP/CLI-транспортами для всех четырёх маршрутов: порядок ролей, 8/9 пар, граница 16 000, вопросы 0/4000/4001, удаление целых пар; Claude — stdin и аргументы без запуска установленного клиента/auth status. Ошибка/таймаут/неполный SSE не загрязняют историю. Транспорт намеренно игнорирует отмену и поздно возвращает ответ/ошибку после нового разговора, Stop, смены модели при прежнем ID, A→B→A и входа/выхода: нет старого текста, записи, речи или возобновления прослушивания. Проверить также сброс на границе завершения и отсутствие передачи истории новому провайдеру. Регрессии: локальные команды, обычная следующая голосовая сессия, сохранение темы и остановка уже начатой речи.

Адресные проверки, затем подходящий полный .NET-набор и проверка собственного окна без захвата рабочего стола. Реальная ручная проверка отдельно: вопрос с двумя пунктами → уточнение второго → «Новый разговор» → вопрос без прежнего контекста. Фиктивные тесты не подтверждают качество всех моделей в сети.

## 2. ИИ вызывает существующие локальные навыки — принят с голосовым прерыванием

Реализованы явная задача и отдельное разрешение по умолчанию выключенное, прямой ChatGPT Responses с `jarvis_local` function tools, общий типизированный исполнитель, до трёх действий/четырёх обращений/90 секунд, точное наблюдение EXE-окна перед переключением, отмена, инвалидация и запрет повторов. Только включённые EXE; другие подключения остаются разговорными. Полные финальные проверки **399/399 Core и 49/49 App**, независимое read-only ревью принято; собственное окно и 32 UI render-сочетания проверены. Описание, границы и тестовые точки: [AI-LOCAL-ACTIONS.md](AI-LOCAL-ACTIONS.md).

**Отдельная обязательная подзадача voice-interrupt завершена:** ограниченный режим speech-worker принимает точные «останови задачу» / «отмени задачу» / `stop task` / `cancel task` только во время задачи, начатой голосом при уже активированном микрофоне. Текстовая задача не включает микрофон; остальные фразы не идут в router/ИИ/журнал. Capture/поздние события закрываются при Stop, новом разговоре, смене scope/аккаунта/разрешения, перезапуске/dispose и завершении задачи до TTS. Медиакоманда «стоп» сохраняет прежнее значение. Полные проверки после интеграции: **399/399 Core, 51/51 App, 99/99 Python**, ruff без замечаний; независимое read-only ревью принято. Контракт и границы ручной проверки — [TASK-VOICE-INTERRUPT.md](TASK-VOICE-INTERRUPT.md). Реальный микрофон/модели не запускались; этап 3 здесь не начинался.

**Первый результат:** явная задача «открой [приложение из каталога], затем переключись на него». Видны текущий шаг и результат; JARVIS выполняет шаг существующим навыком, возвращает наблюдение модели, продолжает либо сообщает причину остановки. Начальный предел — три шага с действиями, ограниченное число обращений к модели и общее время. Для разработки — фиктивная цель/собственное тестовое окно.

**Зависимости:** принят этап 1; исполнитель задач с отменой; строгие схемы аргументов; проверка актуального tool calling конкретного провайдера перед реализацией. Первый выпуск может поддерживать один проверенный адаптер; остальные остаются разговорными с явным сообщением о недоступности действий. Подписочное подключение не означает поддержку всех инструментов.

**Границы:** небольшой разрешённый список навыков и включённых ID каталога; никаких shell-команд, свободного кода и произвольного EXE от модели. Аргументы и цель проверяются перед исполнением; неоднозначность требует выбора. Отдельная настройка разрешает действия, вход в аккаунт сам её не включает. Покупки, отправки, удаление, питание и закрытие окон с риском потери данных вне первого результата.

Проверить `SkillResult.Verified` каждого включённого навыка: запуск процесса не доказывает готовность окна, принятие команды не доказывает воспроизведение. Подтверждать конкретное наблюдаемое состояние; без наблюдения — «не подтверждено», без зависимого следующего шага. Не менять глобально смысл флага без аудита потребителей.

**Готовность и проверки:** двухшаговый сценарий; неизвестный ID/неверные аргументы не доходят до действия; неподтверждённый шаг прерывает зависимую цепочку; повтор ответа не дублирует действие. Stop во время запроса, между планом и действием, между шагами и после позднего ответа запрещает дальнейшее выполнение. Уже выполненное внешнее действие не откатывается автоматически. Голосовую остановку задачи отделить от существующего медиазначения «стоп». Автотесты используют подставные навыки и собственное окно; реальные приложения — отдельная ручная проверка.
