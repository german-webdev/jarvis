# Установка и распространение JARVIS 0.10.0

Готов автономный офлайн-установщик `artifacts/release/JARVIS-Setup-0.10.0-win-x64.exe`. Для передачи нужен один этот EXE. Рядом размещаются SHA-256 и краткая инструкция. Внутри: приложение WPF, .NET 10.0.14, переносимый CPython 3.12.13, зависимости из `uv.lock`, Vosk, Silero VAD, Whisper small CPU INT8 и голоса Piper. Пользователь не устанавливает SDK или Python.

## Поддерживаемая платформа

Windows 10 2004 / build 19041 и новее, Windows 11; Intel/AMD x64. Установщик не принимает Windows 7/8, 32-битную Windows и ARM. Рекомендуются 8 ГБ ОЗУ и 4 ГБ свободного места на время установки; это ориентир, а не измерение минимальной конфигурации. Локальные команды работают без сети, нейросетевые подключения необязательны. Ollama и Claude Code устанавливаются отдельно, если выбран соответствующий способ подключения.

## Установка и профиль

- Inno Setup 6.7.4, русский и английский мастер; установка для текущего пользователя, `PrivilegesRequired=lowest`.
- По умолчанию `%LOCALAPPDATA%\Programs\JARVIS`; ярлык «Пуск», необязательный ярлык рабочего стола и запись в установленных приложениях.
- Маркер `jarvis.install.json` отделяет установленную версию от разработки. В установленной версии данные — `%LOCALAPPDATA%\JARVIS\data`, временные файлы — `%LOCALAPPDATA%\JARVIS\work`. Ресурсы и среда запуска читаются из папки установки.
- Данные не входят в установщик и не удаляются деинсталлятором. Автозапуск и микрофон по умолчанию выключены. При удалении убирается только запись автозапуска, указывающая на удаляемый EXE.
- Перед установкой/обновлением полностью выйти из JARVIS. Установщик проверяет mutex; принудительно завершать чужой рабочий процесс он не должен.
- Переход с старого прототипа пока без автоматической миграции: исходная папка `data` остаётся на месте. Отдельный перенос допустим на том же Windows-профиле с резервной копией; сессии DPAPI не предназначены для переноса другому пользователю.

## Сборка

На подготовленном компьютере: `scripts/build-installer.ps1`. Компилятор `.tools/inno/ISCC.exe` можно заменить параметром `-InnoCompiler`. Полный payload каждый раз создаётся в новой папке `artifacts/installer-build-<timestamp>`. Скрипт проверяет тесты, публикует self-contained win-x64, формирует комплект по разрешённому списку, запускает проверку моделей/синтеза, затем компилирует EXE и пишет SHA-256. Результаты не коммитятся в Git.

`prepare_installer.py` не копирует `data`, `.venv`, `.git` или рабочие каталоги. Python устанавливается в отдельный runtime из зафиксированных пакетов с проверкой хешей; `._pth` изолирует его от системного Python. Модели проверяются по `models.lock.json`. MSVC DLL поставляются рядом с Python. Лицензии, карточки моделей и архивы исходников отдельных зависимостей включены в `third-party`. `payload-sha256.json` проверяется скриптом `verify_installer.py`.

## Проверки и ограничения

Автотесты: 286 Core + 13 Windows + 33 Python; ruff. Автономный `Jarvis.exe --check-installation <report.json>` не включает микрофон и воспроизведение: проверяет загрузку всех моделей и синтез фразы. Проверка выполнялась с неверными внешними PYTHONHOME/PYTHONPATH/DOTNET_ROOT; загружена именно включённая .NET-среда.

Проверка установщика использует отдельный AppId, без пользовательских ярлыков и без конфликта с запущенным прототипом. Установка, повторная установка и удаление проверяются в отдельной папке с пробелом и кириллицей. Это не равно тесту на чистой Windows без установленного ПО: такую проверку ещё нужно провести на другом ПК.

Установщик не подписан сертификатом издателя. Автоматическое обновление, автоматическая миграция прототипа, восстановление предыдущей версии, подпись и отдельная ARM-сборка остаются будущими задачами.

Кириллица в пути: Vosk требовал UTF-8 ACP. В манифест только встроенного `python.exe` добавлен `activeCodePage=UTF-8`; системная локаль не меняется. Повторная загрузка моделей и синтез успешно проверены в папке `Установка JARVIS`. Основание: [Microsoft — UTF-8 code page per process](https://learn.microsoft.com/en-us/windows/apps/design/globalizing/use-utf8-code-page). Для self-contained EXE в `AppHostDotNetSearch` обязательно оставлять `AppLocal`.
