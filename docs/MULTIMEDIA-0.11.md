# Мультимедиа · 0.11.0

## Управление воспроизведением

Предпочтительный музыкальный плеер больше не перехватывает все медиакоманды.

- «Пауза», «стоп», «останови», «продолжи», «дальше», «назад» выбирают текущее воспроизведение Windows. Единственный играющий источник имеет приоритет перед источниками на паузе. При нескольких играющих используется текущая медиасессия Windows; при неоднозначности действие не выполняется.
- «Останови музыку», «выключи музыку», «продолжи музыку», «музыку тише» используют выбранный музыкальный плеер. Если он исчез, эти явные музыкальные команды не переключаются на браузер.
- «Пауза видео», «поставь видео на паузу», «продолжи видео» исключают распознанные приложения только для музыки. Это фильтрация источников, а не анализ содержимого вкладки; музыка в браузере тоже может попасть в этот набор.
- «Включи музыку» запускает предпочитаемый плеер. Без предпочтения один подходящий плеер выбирается автоматически, несколько — через существующее уточнение.
- «Дальше» / «назад» переключают трек. «Перемотай вперёд» / «перемотай назад» запрашивают сдвиг на 10 секунд в доступном диапазоне. Эти операции зависят от поддержки плеера.
- Короткие команды громкости выбирают текущий источник. Изменение громкости требует связать его с приложением; если это невозможно, JARVIS предлагает отдельную системную команду, а не меняет общую громкость молча.

Play/Pause подтверждаются состоянием Windows. Для переключения трека и перемотки сообщается только передача запроса. Несколько сессий с одним SourceAppUserModelId не выбираются произвольно. Последний успешно управляемый источник сохраняется только в памяти для возобновления, если Windows не указывает однозначный источник.

Основа: [медиасессии Windows](https://learn.microsoft.com/en-us/uwp/api/windows.media.control.globalsystemmediatransportcontrolssessionmanager?view=winrt-26100). Приложение должно публиковать такую сессию. Это не универсальное управление любым звуком на ПК; нажатия клавиш браузеру не посылаются. ИИ и изображение экрана не используются.

## Раздел JARVIS → Мультимедиа

Один раздел объединяет вкладки «Плееры», «Папки», «Музыка и видео». В настройках вместо прежней вкладки «Музыка» находится переход в этот раздел.

**Плееры.** Из каталога и результатов поиска показываются распознанные музыкальные/видеоприложения: по известным именам и названиям исполняемых файлов, например Yandex Music, Spotify, AIMP, VLC, PotPlayer, MPC, Windows Media Player. Блокнот, Word, игры Steam и сайты туда автоматически не попадают. Это ограниченный набор правил, а не доказательство возможностей любого приложения. Неизвестный плеер можно явно добавить вручную. Запуск и связь с медиасессией зависят от приложения; особенно это относится к ярлыкам и нестандартным идентификаторам.

**Папки.** Пользователь добавляет нужные папки либо нажимает «Папки Windows» для существующих папок «Музыка» и «Видео». «Найти файлы» запускает фоновый поиск с остановкой. Все диски автоматически не обходятся. Поддерживаются вложенные папки, пропускаются ссылки и системные записи; пределы — 10 000 медиазаписей, 100 000 просмотренных записей и 32 уровня вложенности. Недоступные папки и достижение пределов сопровождаются предупреждением. Сканирование ничего не воспроизводит.

**Файлы.** Индексируются названия аудио и видео по разрешённым расширениям. Можно добавить отдельные файлы, искать в списке, переименовывать записи и задавать псевдонимы. Повторный поиск добавляет новые записи и сохраняет пользовательские имена; исчезнувшие файлы пока убираются вручную. Удаление записи или папки из каталога не удаляет файлы с диска.

Команды: «Включи фильм [название]», «Включи видео [название]», «Включи песню [название]», «Включи трек [название]», «Запусти плеер [название]». Одноимённые записи уточняются. Файл передаётся приложению Windows по умолчанию; факт начала фильма/песни не заявляется. «Открой папку [название]» / «Запусти папку [название]» открывают добавленную папку в Проводнике, не создают плейлист.

Каталог — `data/media.json` соответствующего профиля, вне Git и установщика. Изменения окна применяются по «Сохранить». Переход к мультимедиа из настроек не должен возвращать устаревшее предпочтение при последующем сохранении настроек.

## Проверки

311 Core + 13 Windows-тестов, 33 Python-теста, ruff. Регрессии покрывают играющий браузер при закрытой/приостановленной музыке, явный выбор музыки, текущую сессию Windows, неоднозначность и одинаковые SourceId, фильтрацию приложений, типы и имена файлов, уточнение, сохранение каталога, отмену и лимиты сканирования.

Окно отрисовано вне рабочего экрана на тестовом профиле: русский/английский, три вкладки, минимальный размер, поиск. Проверено, что настройки не перезаписывают более свежий выбор плеера. Скриншоты рабочего стола и аудио пользователя не собирались.

Реальный сценарий «Яндекс Музыка выбрана → играет YouTube → пауза → продолжи» на браузере и микрофоне пользователя ещё требует подтверждения. Установка на чистую стороннюю Windows также не проверена.
