## Следующий предлагаемый шаг — обсуждение перед новой сессией

Одна проверяемая задача: обычная просьба «Открой YouTube и найди видео про котиков» должна целиком передаваться выбранной нейросети, когда локального исполнения недостаточно. Модель должна выполнить её через подключённый браузерный инструмент, получить реальные результаты и показать подтверждённый итог. Специальный префикс «Задача ИИ» и ручное составление сценария не должны требоваться.

Для этого сначала проверить совместимость существующего входа по подписке с вызовами инструментов, затем подключить один готовый браузерный MCP-модуль (кандидат — Microsoft Playwright MCP) через общий слой выполнения в JARVIS. Не привязывать общий интерфейс инструментов к названию ChatGPT; фактическую поддержку проверять для каждого подключения. Не импортировать плагины/аккаунты Codex автоматически и не переключать подписку на платный API без указания пользователя.

Проверка результата: локальные простые команды остаются рабочими; сложная просьба не заканчивается «Команду не понял» при доступном ИИ; браузер реально выполняет поиск; остановка прерывает задачу; ошибка инструмента возвращает управление. До такой проверки не объявлять возможность готовой. Почта и управление другими приложениями — последующие интеграции, не расширение этой первой задачи. Новые разделы интерфейса, сценарии и «Новый разговор» не возвращать.

Источники для следующей сессии:
- https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations — вызовы function/custom tools поддерживаются; hosted MCP на маршруте подписки не поддерживается; локальные MCP-инструменты могут выполняться клиентом.
- https://developers.openai.com/plugins/concepts/plugins — навыки и MCP-инструменты имеют разные роли; плагины могут зависеть от среды исполнения.
- https://github.com/microsoft/playwright-mcp — кандидат готового браузерного инструмента, пока не подключён и не проверен в JARVIS.
