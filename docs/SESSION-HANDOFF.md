## Формат совместной работы

- Общаться по-русски, коротко и конкретно; интерфейс должен быть понятен нетехническому пользователю. Название продукта — JARVIS, английскими буквами.
- Базовые команды локально, ИИ по необходимости. Подключения необязательны, никаких автоматических личных входов или оплаченных тестовых запросов.
- Не заставлять пользователя искать EXE официального клиента. ChatGPT теперь использует прямой браузерный OAuth; Claude пока использует обнаруживаемый официальный компонент, это ограничение обозначать явно.
- Не объявлять готовность по одному факту компиляции. Разделять автоматические тесты, вход аккаунта, фактический ответ модели и пользовательское подтверждение.
- Сначала сделать конкретное исправление и проверки, затем просить короткую проверку пользователя. Не повторять уже подтверждённые шаги.
- Не захватывать экран и не управлять чужими окнами без необходимости: предыдущий захват вызвал жёлтую рамку монитора и вопрос пользователя. Для проверки оформления можно рендерить собственное WPF-окно вне рабочего экрана. Просить пользователя самому перезапустить JARVIS.
- Не запускать подагентов без явной просьбы. Не переписывать рабочие каталоги, сессии и настройки. Политику памяти не менять; эта передача находится в документации проекта.

## Архитектура и важные точки

- `src/Jarvis.App/MainViewModel.cs`: цикл микрофон → worker → команда → ответ, session ID, отмена, watchdog. Не принимать устаревшие события предыдущей сессии.
- `speech/jarvis_speech/interaction.py`, `segmenter.py`: имя и сбор фразы. Не обрезать фразу по таймеру ожидания, если речь уже началась.
- `src/Jarvis.Core/CommandRouter.cs`, `LaunchConversation.cs`, `NameVariants.cs`: локальные команды, уточнения и варианты имён. Точное совпадение Word должно побеждать нечёткое WARDOGS.
- `src/Jarvis.App/Services/BuiltInSkills.cs`: действия; `WindowControl`, `MusicPlayback`: окна и выбранный медиаплеер. Не переключать медиакоманду молча на YouTube при исчезновении выбранного плеера.
- `HelpWindow.xaml/.cs`: новая справка с категориями и поиском. Примеры команд русские и в английском интерфейсе, поскольку английское ASR пока не реализовано.
- `AssistantSettings`: новые `WakeSound=true`, `FollowUpListening=true`; старый JSON получает эти значения по умолчанию. Обе опции в «Настройки → Поведение».
- Сигнал — локальный короткий тон, не TTS. Захват речи при сигнале не прерывается, чтобы сохранить команду, произнесённую сразу после имени. Проверить влияние акустического эха на реальном устройстве.
- Продолжение: только голосовой режим ожидания имени; после ответа и короткой паузы на затухание звука запускается `mode=command, wait_seconds=5`. Тишина возвращает ожидание имени без голосового сообщения. Уточнение выбора имеет отдельный десятисекундный цикл. Кнопка Stop/Esc отменяет оба цикла.
- `AiService`, `ChatGptSignIn`, `ChatGptPlanClient`: прямой ChatGPT OAuth, PKCE, временный IPv4 loopback listener, проверка ID token/JWKS/state/nonce, DPAPI, refresh/revoke, Responses SSE. Успех ответа — только `response.completed`.
- `SubscriptionClient`: путь Claude Code находит автоматически; собственный каталог профиля, без копирования глобальной авторизации. Старый код Codex CLI ещё есть внутри класса для совместимости тестов, но основной ChatGPT-маршрут его не использует.
- `Localization/strings.json` и `Ui`: русские исходные строки, английские переводы, ключи XAML — SHA256 первых 12 hex. Новые элементы локализовать.

Сначала JARVIS спрашивает подтверждение; «Подтверждаю» выполняют действие один раз. Любой другой ответ отменяет запрос. Голосовой ответ ждёт 10 секунд без повторного имени; текстовое подтверждение действительно 30 секунд. Stop/Esc отменяют запрос. Перед действием прослушивание останавливается; после пробуждения нажать «Начать». Гибернация и сон зависят от конфигурации Windows, JARVIS не включает их в системе автоматически.

Реализация питания: `PowerConfirmation` — отдельный одноразовый запрос до AI-routing; `PowerControl` — Windows-адаптер с `IPowerControl` для подмены в тестах. Выключение/перезагрузка: системный `shutdown.exe /s|/r /t 0`, без `/f` (ненулевой `/t` подразумевает принудительное закрытие). Сон/гибернация: WinForms `SetSuspendState`, `force=false`, `disableWakeEvent=false`. Ошибка синтеза или Stop до окончания реплики не выполняют действие. Автотесты не вызывают реальное питание ПК; полный голосовой сценарий и переходы Windows ещё должен проверить пользователь в удобный момент.

Проверки дополнения питания: 285 Core + 13 Windows-тестов пройдены. Windows-тест прогоняет четыре действия через подставной `IPowerControl`, проверяет отсутствие вызова до подтверждения, отмену, Stop и невозможность обойти подтверждение через запрос к ИИ. Core проверяет варианты слова, отрицания, составные фразы, срок и одноразовость подтверждения. Проверены аргументы выключения без запуска процесса. Раздел справки проверен рендерингом собственного окна при минимальном размере; сборка опубликована в `artifacts/prototype`. Python-код в этом дополнении не менялся.

Системные методы: [Microsoft — shutdown](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/shutdown), [Microsoft — SetSuspendState](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.application.setsuspendstate?view=windowsdesktop-10.0).
