# Голосовая остановка локальной задачи

9 ноября 2026. Обязательная подзадача между этапами 2 и 3 функционального плана. Реализация и проверки завершены; независимое read-only ревью принято без открытых P1/P2. Реализация локальная, поверх текущего рабочего дерева 0.13.5. Не меняет авторизацию, версию, установленное приложение или установщик. Этап 3 здесь не реализуется.

## Поведение

Во время локальной задачи ИИ, **начатой голосом при уже включённом микрофоне**, JARVIS принимает только точные команды:

- «останови задачу» / «отмени задачу»;
- `stop task` / `cancel task`;
- те же команды с необязательным обращением «Джарвис» / `Jarvis`, включая существующие варианты написания обращения из `AiRouting.IsStopTask`.

Допускаются регистр, пробелы по краям и завершающие `. ! ?`, как в существующем точном контракте. Слова перед/после команды не разрешают остановку. Обычный «стоп» остаётся медиакомандой в обычном режиме; во время задачи эта и любые другие фразы игнорируются. Они не выводятся в UI/журнал и не отправляются нейросети или обычному обработчику команд.

Текстовая задача, импорт аудиофайла и обычный разговор с ИИ этот режим не включают. Одного флага происхождения голосом недостаточно: в текущей сессии должно быть подтверждено реальное начало захвата. Авторизация сохраняется через обычное временное отключение микрофона на стадии распознавания исходной команды; она не переживает Stop или новую сессию. Запрос, для которого выключено разрешение локальных действий, не включает прерывание.

Существующая подпись «JARVIS слушает» отражает состояние захвата, в том числе во время выполнения задачи. Новые экраны, постоянные поясняющие подписи и дополнительные настройки не добавлены. Остановка отменяет оставшуюся работу; уже выполненные запуск/переключение не откатываются.

## Владение и завершение

`MainViewModel.BeginTaskVoiceInterrupt` / `EndTaskVoiceInterrupt` ограничивают время захвата одной выполняемой задачей. Это пара для повторного использования будущим локальным исполнителем сценариев: получить владельца непосредственно перед выполнением, передать текущий `_operation.Token` исполнителю, освободить **того же владельца в finally до результата/TTS**. Проверка разрешений самого сценария остаётся у вызывающего кода; разрешение локальных действий ИИ проверяется в текущем `AnswerWithAiAsync(..., localTask: true)`.

Владелец хранит отдельную отрицательную capture-session, исходную `_session` и revision разговора. Capture-session никогда не используется снова; обычные голосовые сессии остаются положительными. Входящий `task_stop` проверяется повторно через `AiRouting.IsStopTask`, а также по владельцу, текущей сессии, revision и токену. Наличие владельца задаёт время доступности остановки. События отдельного режима не проходят обычный switch `transcript/processing/empty`; запоздалые события исходной записи после принятия команды также не меняют фазу выполнения.

Stop, новый разговор, смена модели/подключения/аккаунта, отключение ИИ/разрешения, перезапуск, dispose и завершение задачи закрывают захват. Позднее завершение предыдущего runner не может освободить владельца следующего. При dispose UI/session/capture инвалидируются **до** отмены сервиса: иначе синхронное завершение отмены могло успеть показать/озвучить служебный ответ. Успех/ошибка задачи прекращает capture и отправляет reset worker до первого `synthesize`.

`IAudioService` и `IWorkerClient` — узкие подставные границы для тестов, production по-прежнему использует Wasapi/существующий Python worker. Каждый PCM/error callback несёт неизменяемую сессию породившего его захвата. Старый callback, уже пересёкший проверку устройства при Stop/Start, не получает номер новой задачи. UI не ждёт завершения распознавания для выполнения Stop.

## Speech-worker и ограничения

Отдельный режим `task_interrupt` использует существующий VAD/Segmenter и локальный `Engine.recognize`. Максимальная реплика — 4 секунды; тишина и нерелевантный текст оставляют режим активным. Worker отправляет только `task_stop` для точного совпадения, без обычных промежуточных/текстовых событий. Режим получает собственные короткие RU/EN prompt/hotwords, без каталога и предыдущего выбора; автоматическое определение языка используется только здесь. Обычное распознавание сохраняет русский язык и прежний словарь.

Очереди ограничены: до 16 ожидающих PCM-пакетов для interrupt на каждой стороне, пакет не более секунды PCM16 mono 16 kHz; обычный wake/command сохраняет прежнюю ёмкость 128. Это важно для `keep_capture` во время распознавания имени. При переполнении interrupt лишние пакеты отбрасываются. Управляющие start/cancel/transcribe заменяют накопившуюся работу: старый PCM не задерживает новую сессию или TTS за всей очередью. Приём нового управляющего сообщения меняет поколение worker; результат уже выполняющегося ASR старого поколения подавляется.

Нативный вызов ASR нельзя принудительно оборвать внутри Python-потока. Отменённый результат отвергается и worker переходит к актуальной команде после возврата этого вызова. Ограниченные очереди не являются гарантией задержки распознавания: фактическая скорость зависит от CPU и модели. Время самой локальной задачи сохраняет лимит 90 секунд; UI/кнопка Stop работают независимо от ASR. Ошибка worker/capture отменяет задачу и освобождает занятость; существующие восстановление/перезапуск остаются доступными.

## Проверки

Автоматические проверки не открывают реальный микрофон, не воспроизводят звук, не запускают модели/личные приложения и не обращаются к аккаунтам в сети. HTTP/аккаунты/каталог синтетические; окно принадлежит тестовому процессу.

Финальный полный прогон: **399/399 Core, 51/51 App, 99/99 Python**, `ruff check speech tests/python` — без замечаний. .NET Release, `--no-restore -p:UseSharedCompilation=false`, без предупреждений сборки. Python — локальная `.venv`, `-B`, offline. Новые проверки: 2 самостоятельных Windows-теста, расширенный существующий STA lifecycle и 29 Python cases; полного нового набора UI-рендеров не требовалось, поскольку разметка/подписи не менялись.

- `tests/python/test_task_interrupt.py`: fake PCM проходит существующий сегментатор и fake engine до `task_stop`; все четыре команды/обращения, отрицательные фразы, ignore → следующая команда, длительная тишина, ограниченный размер реплики/буфера, cancel/reset, отдельные bilingual параметры ASR без наследования каталога/choice. Полный worker loop проверяется с поздним ASR после нового поколения, error → новый start и cancel → TTS без старого PCM. Отдельно сохранён обычный буфер 128.
- `TaskVoiceInterruptViewModelChecks` вызывается внутри единственного существующего STA lifecycle. Проверяет **ожидающую ответа моделью локальную задачу**, голосовую остановку до внешнего действия, повторный запуск с поздними событиями/PCM/ошибками, отсутствие новых запросов/логов от игнорируемых фраз, завершение capture до TTS. Все причины инвалидации проверены с поздним ответом fake HTTP. Текст/неподтверждённый capture/обычный голосовой AI не включают interrupt. Источник аудио — `FakeAudio`, не устройства Windows.
- `TaskVoiceInterruptTransportTests`: насыщение очереди, сброс перед TTS/новой сессией и сохранность прежней ёмкости обычного wake. Python-процесс не запускается.

Реальное качество/задержка RU/EN распознавания и голосовая остановка на пользовательском устройстве требуют отдельной ручной проверки. Подставные тесты подтверждают протокол, отмену и жизненный цикл, но не заменяют её.

## Ручной сценарий после установки пользователем

При включённом разрешении локальных задач начать прослушивание, голосом задать явную локальную задачу и, пока она ожидает модель/наблюдение окна, произнести «останови задачу». Проверить прекращение захвата и отсутствие следующего действия. Повторить с «отмени задачу» / английскими вариантами. «Стоп» и посторонняя фраза во время задачи не должны менять задачу или появляться в журнале. Затем начать такую же задачу текстом: микрофон должен оставаться выключенным. После успешного завершения голосовой задачи захват выключается до ответа. Кнопку Stop проверить отдельно; выполненное до неё действие не считается отменённым.
