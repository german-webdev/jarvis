## Согласованные решения

- Основное направление: графит и бирюза. Визуальный ориентир — `design-concepts/multimedia-graphite-2026-11-09.png`; светлый вариант — соседний макет. Картинки не являются работающим интерфейсом.
- Единое окно с постоянной боковой навигацией. Разделы размещаются внутри него; отдельные диалоги остаются для короткого ввода, выбора файлов и подтверждений.
- Сохранить WPF, существующее поведение, русскую/английскую локализацию, профили и подключения.
- Рабочий выбор «Оформление»: системное / светлое / тёмное. Основной режим по умолчанию — тёмный; системное следует теме приложений Windows. Явный выбор сохраняется.
- В 0.12.3 «Цветовой стиль» — недоступный список «В разработке». В ближайшей очереди он становится рабочим после кнопок/сайдбара и до компактного режима; порядок указан выше.
- Работа и сборка локальные. GitHub CI/push не запускать. Рабочее установленное приложение пользователя автоматически не заменять.

## Границы текущей реализации

Для этапа 2 не подставлять демонстрационные названия и длительности в продукт. Блок «Сейчас воспроизводится» переносить из макета только с реальными данными системного источника и проверенным управлением. Если источник отсутствует/не поддерживает действие, показывать соответствующее состояние. Не запускать музыку/видео пользователя ради визуальной проверки.

Главное в первом проходе — единая структура и удобные реальные сценарии. Не добавлять одновременно новые ИИ-инструменты, поиск музыки в интернете, звуковой набор, обновления с GitHub или другие независимые функции.

## Результаты реализации и проверки · 9 ноября

- `WorkspaceShell` — постоянная боковая навигация и строка состояния. `WorkspacePage` — общий жизненный цикл разделов, запрос выхода и проверка несохранённых правок. `Views/*Page.xaml` — страницы; прежние классы окон сохранены как небольшие совместимые оболочки для диалоговых вызовов.
- Каталог приложений и игр сохранён единым разделом, как в существующих данных. Разделение на независимые каталоги не выполнялось.
- «Мультимедиа» показывает реальные сведения SMTC, доступность паузы/продолжения, отсутствие/недоступность источника. В тестовом рендере наблюдение за пользовательским воспроизведением отключено. Демонстрационные названия из макетов не встроены в приложение; фиктивных длительностей и прогресса нет.
- Выбор темы находится в «Настройки → Приложение → Оформление». Сохраняется `Appearance`; старые профили получают `dark`. Системный режим читает тему приложений Windows и слушает изменения предпочтений. Палитры общие для всех разделов; стандартные элементы используют встроенные шаблоны Fluent WPF.
- 315 Core, 18 Windows, 33 Python проверок пройдены; ruff пройден. Windows-проверка покрывает навигацию к настройкам, сохранение светлой темы, отмену изменения, недоступность цветового стиля, применение системной темы, выход, трей и голосовые сценарии с подставными действиями питания.
- Получены 48 рендеров собственных страниц: 6 разделов × RU/EN × тёмная/светлая × обычный/минимальный размер. Проверены поиск в мультимедиа и признак несохранённых изменений. Минимальные рендеры экспортированы в масштабе 150%; это не тест переключения DPI монитора. Исправлен перенос длинных пояснений внутри прокручиваемых областей.
- Материалы проверки: `work/ui-redesign-checks/`; промежуточные данные не являются пользовательским профилем и не входят в установщик.

- Реальная смена темы Windows при выбранном «Системное»; автоматическая обработка события реализована, настройки Windows во время тестов не изменялись.
- Клавиатура и масштаб на рабочем мониторе пользователя. Системное переключение DPI 125/150/200% не имитировать утверждением о полноте проверки по изображениям.

Основа стандартных элементов: [Microsoft — Fluent и ThemeMode в WPF](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/whats-new/net90). Точный перечень проверок выше важнее общего статуса этапа.
