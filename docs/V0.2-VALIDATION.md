- 15 Python-тестов прошли: выделение речи, имя с паузой, сохранение начала команды без паузы, одиночное имя не становится командой, тайм-аут, отмена, формат и ограничение уровня звуковых эффектов.
- Ruff и `git diff --check` пройдены.

## Реальные модели с синтетическим звуком

`scripts/test_speech.py` запускает отдельный речевой процесс и передаёт PCM-фрагменты, не включая микрофон.

| Сценарий | Результат |
|---|---|
| Имя и команда в одной фразе | Имя отделено, команда «Запусти, браузер, пожалуйста» получена |
| «Джарвис» → две секунды тишины → команда | Во время паузы нет transcript/empty/timeout; затем получена команда «Запусти браузер, пожалуйста» |
| Только имя и тишина, ожидание 4 секунды | Получен command_timeout, без передачи имени маршрутизатору |
| Тишина без речи | Отброшена |
| Денис: natural / robot / radio | Все три варианта синтезированы в WAV |

Распознавание самой команды после имени в контрольном прогоне заняло около 0,94 секунды CPU. Это время ASR, а не общая задержка ответа. В файловом и кнопочном тесте синтетической фразы с именем распознаватель иногда заменяет «запусти» на «опусти»; этот результат не подтверждает выполнение команды. Такой текст ограниченный маршрутизатор отвергает. Тест проверяет речевой тракт; точность живой речи оценивается отдельно.

## Проверка интерфейса

Окно запущено через `Start-Jarvis.cmd` в обычном сеансе Windows. Проверены главный экран, отдельное окно настроек, выбранный Audient iD14, вкладки голоса и поведения. Предпрослушивание Дениса с эффектом завершилось без ошибки, интерфейс вернулся в готовность. Режим ожидания имени сохранён через интерфейс; запись подтверждена чтением локального файла настроек. Это подтверждает завершение тракта воспроизведения, но субъективное качество голоса оценивает пользователь.

## Ограничения проверки

Предыдущий прототип прошёл живой сценарий с микрофоном Audient iD14 и подтверждением пользователя: браузер открылся, ответ слышен. Для версии 0.2 отдельно нужны живая оценка паузы после имени и субъективная оценка нового голоса. Синтетические тесты не доказывают устойчивость к телевизору, музыке, длительной работе и игровым звукам.

Исходники и модельные манифесты входят в Git; локальные настройки, веса, аудиопримеры и отчёты в `work` — нет. Существующий отчёт о первой версии сохранён в [PROTOTYPE-VALIDATION.md](PROTOTYPE-VALIDATION.md).
