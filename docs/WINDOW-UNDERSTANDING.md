# Понимание выбранного окна Windows

> Исторический документ. План и промпт отменены последующим запросом пользователя; описание выпуска не отражает исходники после отката. Актуальное состояние: [ROLLBACK-2026-11-09.md](ROLLBACK-2026-11-09.md). Сабагентов не использовать.

9 ноября 2026 · этап 5 реализован и прошёл независимое read-only ревью кода, тестов и собственного рендера без открытых P1/P2. Первый результат ограничен Windows UI Automation: чтение доступных подписей одного явно выбранного окна и выбор одной однозначной вкладки с проверкой `IsSelected`. Универсальное управление рабочим столом, снимки, vision и внешние запросы ИИ не добавлены.

## Использование

Открой раздел **«Окно»**, нажми **«Обновить список окон»**, явно выбери окно и нажми **«Обновить описание»**. Видны подписи и типы доступных элементов, отключённые состояния и выбранные вкладки. Выбери строку вкладки и нажми **«Выбрать вкладку»**. Недоступные и повторяющиеся названия не исполняются. После смены выбранного окна прежнее описание очищается.

После явного выбора работают текст и голос: **«опиши окно»**, **«выбери вкладку [название]»**; английские варианты **describe window**, **select tab [name]**. Название должно точно и однозначно соответствовать доступной вкладке (без учёта регистра/нормализации команды). Голосовая операция при уже включённом микрофоне использует существующие **«останови задачу» / «отмени задачу»**. Кнопки и текст микрофон не включают. Переход между страницами не останавливает прослушивание.

## Поставляемая граница

- Core `WindowUnderstanding` хранит одну выбранную цель только в памяти и вызывает `IWindowInspector`. Production `WindowsWindowInspector` запускает собственный `Jarvis.exe --inspect-window` до обычного старта приложения. Отдельный процесс не загружает профиль/аккаунты/worker и завершает работу после одного запроса. UI Automation никогда не исполняется на основном UI-потоке.
- Ограничение каждого helper — 7 секунд; отмена уничтожает helper. IPC через перенаправленные stdin/stdout, без временных файлов с содержимым. Чтение ответа ограничено 65 000 символов. Таймаут и обрыв pipe после отмены различаются по токену, чтобы интерфейс не оставался занят после внутреннего таймаута.
- Список до 40 видимых верхнеуровневых окон текущего desktop. Принадлежность подтверждается HWND, PID, временем старта процесса, путём EXE и session Windows. Проверяются обычный `Default` input/thread desktop, не повышенный токен процесса, видимость, отсутствие минимизации и соответствие корневого окна. Недоступные, повышенные и защищённые цели отвергаются. В тесте список ограничен только PID собственной фикстуры до чтения заголовков других окон.
- Снимок UIA ограничен 180 посещёнными узлами, глубиной 12, 60 именованными элементами, 7000 символами имён и 180 символами на имя. Скрытые, парольные, editable и Document-поддеревья пропускаются. `ValuePattern` и `TextPattern` не читаются. Сохраняются только runtime ID, видимая подпись, тип, enabled и selected; снимки экрана не создаются. Предел/усечение запрещает действие.
- Выбор вкладки: свежий снимок → единственный `TabItem` с доступным `SelectionItemPattern` → helper READY → разрешение основного процесса после проверки отмены → проверка идентичности/фокуса → повторное разрешение runtime ID/имени/типа/enabled → `Select` → новый снимок и `IsSelected=true`. Вызов `Select` сам по себе не считается успехом. Фокус устанавливается Win32/стандартным UIA SetFocus и затем проверяется; отказ Windows завершает операцию. Нет координат, клавиатурного ввода или произвольных кнопок. Изменение только selected при установке фокуса допустимо, изменение идентичности элемента — нет.
- Каждая операция и каждый выбор цели имеют новое поколение; A→B→A не восстанавливает старую работу. Stop, смена цели, новая session, новый разговор/scope ИИ, перезапуск и dispose отменяют незавершённую работу. После await актуальность проверяется перед показом/речью. Уже совершившееся переключение вкладки не откатывается и не объявляется невыполненным.
- Описание остаётся в памяти интерфейса и не записывается в History/журнал, файл или контекст ИИ. Голосовой запрос может озвучить его существующим локальным speech-worker. Обычная пользовательская командная фраза продолжает попадать в существующий журнал команд; автоматическое содержимое UIA туда не добавляется. Ни «Объяснить с ИИ», ни неработающей кнопки vision нет.
- Команды зарезервированы `ScenarioRules`; старый сценарий с такой фразой блокируется и через кнопку запуска. `LocalActionKind`, права ИИ, авторизация и существующие системные действия не расширены.

## Проверки и границы доказательств

**479/479 Core**, **52/52 App**, Release. App включает общий STA lifecycle с проверками текста, отсутствия записи/ИИ, Stop/нового разговора/A→B→A, позднего read без действия, внутреннего timeout, старого подтверждения питания, browser choice, legacy scenario button и голосового interrupt. Успешный голосовой путь отдельно подтверждает освобождение interrupt capture до синтеза. Фиктивные Core провайдеры проверяют дубликаты, disabled/unsupported pattern, усечённый снимок, смену цели, Stop/отмену/dispose до действия и поздний результат действия. Микрофон и звук не запускались. Первый ограниченный запуск тестов не смог соединиться с testhost; разрешённый Windows-прогон завершился успешно.

**Настоящий UIA adapter** проверен через `tests/Jarvis.DesktopProbe --uia-verify` на собственном отдельном WPF-процессе, без старого media-probe маршрута. Отчёт `work/window-understanding/uia-report.json`: все проверки true — собственный PID, доступные подписи, отсутствие password/edit/hidden текста, дубликат/disabled, подтверждённый `IsSelected`, чтение/выбор после изменения размеров и WPF scale 150%, stale runtime ID, изменённое время старта, закрытие, hung helper timeout и отмена. Тестовый hung helper работает только в DesktopProbe. Доступ к чужим окнам/профилям и захват desktop не использовались. Первые прогоны обнаружили честный отказ фокуса и гонку закрытия pipe при kill; после исправлений итоговый собственный сценарий зелёный.

**64 offscreen WPF-компоновки**: RU/EN, dark/light, 1104×681 и 1264×811, развёрнутая/свёрнутая панель, raster scale 100/125/150/200%. Проверены границы кнопок/выбора/списка, фактическая ширина строк и текстовых контейнеров вкладок, доступное имя выбора окна. Собственный стиль строк исключает наследование width48 боковой панели. После добавления девятого раздела уменьшен только вертикальный отступ collapsed navigation с 3 до 1 DIP: кнопки 48×48 сохранены, на минимальной высоте scrollbar больше не пересекает выделение. Повторный рендер всех 64 сочетаний проверяет отсутствие scrollbar у свёрнутой навигации. Отчёт `work/window-understanding-preview/report.json`; просмотрены `dark-ru-collapsed-100.png` и `light-en-full-100.png`. Рендер не открывает окно и не запускает устройства. WPF scale/raster scale не заменяют проверку переключения системного DPI на реальном оборудовании.

Реальные сторонние приложения и голос на устройстве пользователя остаются ручной проверкой после установки: выбрать поддерживаемое окно → обновить описание → выбрать вкладку с уникальным названием → сверить состояние. При unsupported UIA, запрете фокуса или защищённом окне приложение сообщает ограничение; снимков и обхода защиты нет. Проверка реального UAC/secure desktop намеренно не запускалась.

Версия 0.13.5, установщик, пользовательская установка, commit/push и CI этим этапом не менялись. Подготовка общего выпуска выполняется отдельно после приёмки.

## Сверенные первичные источники

- [Microsoft SelectionItemPattern](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/implementing-the-ui-automation-selectionitem-control-pattern): Select и наблюдаемое IsSelected.
- [Microsoft SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow): ограничения foreground и передача права helper через AllowSetForegroundWindow.
- [Microsoft UI Automation Security](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/ui-automation-security-overview): граница защищённого UI; приложение не запрашивает uiAccess и не повышает права.
